# AINAK Multimodal Feature & Data Schema Specification

## 1. Overview

AI AINAK operates as a synchronized multimodal perception and assistive decision system. During offline batch processing, recorded session replay, and demonstration notebooks (Google Colab / local environment), the three sensory branches extract high-dimensional latent representations and metadata, serializing them into NumPy compressed archives (`.npz`). The Multimodal Transformer Fusion network and Decision Engine consume these serialized structures.

This specification documents the array formats, tensor dimensions, value ranges, coordinate conventions, and alignment protocols used across all notebooks and pipeline modules.

---

By default, intermediate and final outputs are stored in `outputs/` (or `/content/drive/MyDrive/AINAK_Colab/outputs/` on Google Colab):

## 3. Sensory Branch Feature Schemas

### 3.1 Vision Branch (`vision_outputs.npz`)

The vision pipeline processes raw video frames ($H \times W \times 3$, RGB) through YOLOv8n object detection, ByteTrack tracking, depth proxy calculation (normalized bounding box area), and temporal looming hazard estimation ($dA/dt$).

| Key | Type | Shape | Description & Value Range |
| :--- | :--- | :--- | :--- |
| `timestamps` | `float64` | `(N,)` | Video frame capture timestamps in seconds (monotonically increasing). |
| `features` | `float32` | `(N, 128)` | Fixed 128-dimensional latent vector per frame.<br>• `features[:, 0:80]`: COCO class detection count histogram.<br>• `features[:, 80:84]`: Primary track normalized coordinates `[x1, y1, x2, y2]` in $[0.0, 1.0]$.<br>• `features[:, 84]`: Depth proxy (normalized bbox area $\in [0.0, 1.0]$).<br>• `features[:, 85]`: Looming hazard factor ($dA/dt \ge 0.0$).<br>• `features[:, 86:128]`: Zero-padded reserved latent dimensions. |
| `frame_indices`| `int64` | `(N,)` | Sequential video frame indices ($0, 1, \dots, N-1$). |
| `loom_hazards` | `float32` | `(N,)` | Looming acceleration rate for detected forward obstacles ($0.0$ indicates no looming). |
| `detections_json` | `string` | scalar | Serialized JSON string containing per-frame bounding boxes, tracking IDs, confidence scores, and COCO labels. |

---

### 3.2 Audio Branch (`audio_outputs.npz`)

The audio pipeline ingests raw 16 kHz or 44.1 kHz mono waveform data, applies 1.0-second sliding analysis windows with 0.5-second hop (or aligned step), processes the audio through the PANNs CNN14 backbone (yielding 2,048-dimensional bottleneck embeddings), and classifies sounds using a 2-layer downstream AudioMLP across 50 ESC-50 environmental classes.

| Key | Type | Shape | Description & Value Range |
| :--- | :--- | :--- | :--- |
| `timestamps` | `float64` | `(M,)` | Timestamp corresponding to the center/end of each audio analysis window in seconds. |
| `features` | `float32` | `(M, 2048)` | High-level acoustic latent representation extracted from the global pooling layer of PANNs CNN14 backbone. Normalized via $L_2$ norm or standardized. |
| `class_indices`| `int64` | `(M,)` | Top predicted ESC-50 class index $\in [0, 49]$. |
| `confidences`  | `float32` | `(M,)` | Softmax probability of top predicted audio class $\in [0.0, 1.0]$. |
| `class_labels` | `string`  | `(M,)` | Human-readable string labels (e.g., `"siren"`, `"car_horn"`, `"dog"`, `"footsteps"`, `"silence"`). |

---

### 3.3 Gesture Branch (`gesture_outputs.npz`)

The gesture pipeline extracts 33 body landmarks via MediaPipe Tasks Pose Landmarker Lite from each video frame, normalizes coordinates relative to the torso center and shoulder width, maintains a sliding temporal FIFO buffer of 24 frames, and passes the $(24, 132)$ sequence through a 2-layer unidirectional GestureLSTM.

| Key | Type | Shape | Description & Value Range |
| :--- | :--- | :--- | :--- |
| `timestamps` | `float64` | `(K,)` | Frame timestamps aligned with video frame capture times in seconds. |
| `features` | `float32` | `(K, 128)` | Latent hidden state vector $h_t$ from the second layer of the trained GestureLSTM. |
| `gesture_indices`| `int64` | `(K,)` | Predicted gesture class index: `0`: No Gesture / Neutral, `1`: Stop / Palm Raise, `2`: Wave / Attention, `3`: Point Left, `4`: Point Right. |
| `confidences`  | `float32` | `(K,)` | Softmax probability score of the predicted gesture $\in [0.0, 1.0]$. |
| `landmarks_detected`| `bool` | `(K,)` | Boolean flag indicating whether pose landmarks were successfully extracted by MediaPipe. |

## 4. Multimodal Fusion & Decision Schema (`fusion_outputs.npz`)

### 4.1 Temporal Alignment Protocol

Because vision and gesture frames arrive at camera framerate ($\sim 30$ fps) while audio embeddings arrive at windowed hops ($\sim 2$ Hz), Notebook 04 synchronizes the modalities using nearest-neighbor timestamp matching within a maximum tolerance window ($\Delta t \le 0.5$ s).

If any modality is unobserved or lost (e.g. camera occluded or silent environment), an all-zeros feature vector is substituted, accompanied by a modality mask:
- Vision missing mask: $\mathbf{m}_v \in \{0, 1\}$
- Audio missing mask: $\mathbf{m}_a \in \{0, 1\}$
- Gesture missing mask: $\mathbf{m}_g \in \{0, 1\}$

### 4.2 Transformer Tensor Contracts

The trained Transformer Fusion module (`fusion.pt`) expects a batch of synchronized tokens:
- Input projection:
  - Vision ($128 \to 128$) via Linear + ReLU
  - Audio ($2048 \to 128$) via Linear + ReLU
  - Gesture ($128 \to 128$) via Linear + ReLU
- Token sequence: $\mathbf{X} \in \mathbb{R}^{B \times 3 \times 128}$ (Tokens: `[Vision, Audio, Gesture]`)
- Architecture: 2 Transformer Encoder layers, $d_{\text{model}} = 128$, $n_{\text{head}} = 4$, $d_{\text{ff}} = 256$, Dropout $= 0.1$.
- Multi-head Output Heads:
  1. `alert_head`: Linear $(128 \to 4)$, producing logits for `["none", "informational", "caution", "urgent"]`.
  2. `priority_head`: Linear $(128 \to 1) \to \text{Sigmoid}$, yielding priority score $\in [0.0, 1.0]$.
  3. `confidence_head`: Linear $(128 \to 1) \to \text{Sigmoid}$, yielding system confidence $\in [0.0, 1.0]$.

### 4.3 Serialized Fusion Output Keys

| Key | Type | Shape | Description |
| :--- | :--- | :--- | :--- |
| `timestamps` | `float64` | `(T,)` | Synchronized timeline timestamps in seconds. |
| `alert_logits`| `float32` | `(T, 4)` | Raw logits for `["none", "informational", "caution", "urgent"]`. |
| `alert_probs` | `float32` | `(T, 4)` | Softmax probabilities over alert categories. |
| `priority`    | `float32` | `(T,)` | Estimated hazard priority score $\in [0.0, 1.0]$. |
| `confidence`  | `float32` | `(T,)` | Multimodal model certainty score $\in [0.0, 1.0]$. |
| `attention_weights`| `float32`| `(T, 4, 3, 3)` | Self-attention matrices per layer/head across `[Vision, Audio, Gesture]`. |
| `decision_bands`| `string` | `(T,)` | Decision Engine mapped operational status: `"immediate_attention"`, `"caution"`, `"gesture_feedback"`, `"informational"`, `"uncertain"`. |

## 5. Verification & Compatibility Assurances

1. **Self-Contained Serialization**: All `.npz` files can be inspected using standard `numpy.load(path, allow_pickle=True)`.
2. **Backward & Forward Compatibility**: Array shapes are validated strictly before downstream consumption. Any missing or malformed key triggers an explicit assertion error rather than silent corruption.
3. **Hardware Agnostic**: Serialization is stored in standard IEEE floating point format and little-endian integers, guaranteeing identical numeric results on x86-64 Windows, Linux, and Google Colab GPU/CPU environments.
